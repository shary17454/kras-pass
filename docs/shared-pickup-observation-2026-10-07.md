## Implementation

`AIBrain.perceived_object_position` now provides bounded, delayed positions for
visible available objects. Initial discovery and subsequent movement use the
configured profile reaction time. Known objects are sampled through the shared
history cadence; each retains at most 32 samples. Hidden/unavailable objects
lose observation credit; destroyed identities are pruned at the next sample.
Configure and round restart reset the map. Availability is never queried before
the visual visibility guard.

The shared nearest-in-group selection uses these positions. Generic power-up
navigation, Collector loot selection/competition/navigation, Courier pickup
navigation, Smasher crate selection/navigation and Relic loose-prize acquisition
and navigation now consume the same delayed positions. Smasher also resets its
colour judgements on reconfiguration. It still classifies rendered colour with
the configured error rate, not the secret bomb flag.

No character stats, shell damage, timers, scoring, input mappings, saves, asset
licences, network protocol or production settings changed. No protected third-
party assets were introduced. This does not claim all AI information channels
are qualified: e.g. carrier-inventory cues and dynamic cue-state timing still
need their separate audit. Tank crate observation keeps its previously tested
availability/line-of-sight-specific implementation.
